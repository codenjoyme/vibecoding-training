# Различия Go и Node.js, обнаруженные во время Python-порта

Это исследовательский журнал Python-порта. Здесь зафиксированы различия, обнаруженные в текущих версиях исходного кода Go и Node.js. Эти наблюдения намеренно записаны здесь, а не исправлены в существующих реализациях в рамках порта.

## Поведение разрешения

| Область | Реализация Go | Реализация Node.js | Выбор Python |
|---|---|---|---|
| Вложенные `sub-configs` | Разрешает только непосредственные sub-configs каждой выбранной группы | Рекурсивно разрешает sub-configs с набором посещённых конфигураций | Использовать рекурсивное разрешение Node.js с защитой от циклов |
| Отсутствующая выбранная группа | Возвращает ошибку вроде `group "name": manifest file not found` | Выводит предупреждение и пропускает конфигурацию | Ошибка для явно выбранной группы верхнего уровня, чтобы опечатка не отключала skills незаметно |
| Отсутствующий вложенный sub-config | Выводит предупреждение и продолжает работу | Выводит предупреждение и продолжает работу | Предупредить в stderr и продолжить |
| Отсутствующий `_global.json` | Молча пропускает файл | Молча пропускает файл | Молча пропускать файл |
| Некорректный `_global.json` | Считает ошибку загрузки признаком отсутствующего файла | Передаёт ошибку разбора JSON | Выбрасывать ошибку манифеста |

## Разбор CLI и вывод

| Область | Реализация Go | Реализация Node.js | Выбор Python |
|---|---|---|---|
| Разбор `--groups` | Использует Go `flag` и позиционные группы; поддерживает повторение и значения через запятую | Вручную принимает значения, разделённые запятыми и пробелами | Принимать значения через запятую, `--groups=value` и позиционные формы |
| Вывод групп в текстовом режиме | `%v` выводит срез Go с квадратными скобками | Объединяет имена через запятые | Использовать вывод Node.js с разделением запятыми |
| PR URL | Поддерживает отдельные HTTPS- и SCP-формы GitHub/GitLab без `expand=1` для GitHub | Нормализует дополнительные SSH-формы и добавляет `expand=1` для GitHub | Использовать более широкую нормализацию URL из Node.js |
| Метаданные в `list --json` | Сначала читает локальный файл, затем использует `git show` | То же поведение: локальный файл и fallback через Git | То же поведение с JSON-отступом в два пробела |

## Создание репозитория

Текст справки Go для `init-repo` говорит, что каталог инициализируется как Git-репозиторий, но обработчик Go только создаёт файлы и печатает последующую команду `git init`. Реализация Node.js явно говорит, что создаётся каталог, и выводит те же последующие команды. Python следует фактическому поведению: создаёт каталог и файлы, но не инициализирует Git.

## Детали Git-операций

- Обе реализации используют системный исполняемый файл Git, а не Git-библиотеку.
- Обе включают `.manifest` в sparse checkout даже при отсутствии выбранных skills.
- Обе возвращаются на обнаруженную ветку по умолчанию после успешного push.
- Обе используют `git stash push -u` для принудительного disable, сохраняя untracked-файлы.
- Обе создают или пересоздают существующую feature-ветку перед коммитом.
- Python использует `subprocess.run` со списком аргументов, что эквивалентно Node.js `execFileSync` и Go `exec.Command`; аргументы Git не передаются через shell.

## Наблюдавшийся дрейф документации

В некоторых сгенерированных документах в каталогах Go и Node.js ещё встречаются старые ссылки на `instructions/.manifest/config.json`, утверждение, что `--groups` обязателен, или пути `skills-cli` из предыдущей структуры. Руководство Python описывает текущее поведение исходников (`skills.json` в корне проекта, необязательные группы и `tools_py`) и не переписывает эти исторические файлы.

## Данные smoke-тестов

Изолированные Docker smoke-тесты используют одинаковые 14 фаз в обеих реализациях. Snapshot Go содержит 166 строк с командами, snapshot Node.js содержит 168, потому что Node.js дополнительно устанавливает и удаляет npm-пакет. В обоих snapshot присутствуют ожидаемые negative cases для отсутствующих групп, дубликатов skills и disable с незакоммиченными изменениями.

Во время обычного второго push одного и того же skill Node.js выводит `fatal: a branch named ... already exists`, после чего удаляет и пересоздаёт ветку. Команда всё равно завершается успешно. Это происходит потому, что Node.js `execFileSync` выводит stderr Git до того, как `createBranch` перехватывает ошибку; Go через `CombinedOutput` скрывает этот промежуточный вывод. Python объединяет stdout/stderr и следует тихому поведению Go.
