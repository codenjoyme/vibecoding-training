# Skills CLI - Snapshot Test Framework

The snapshot test runs inside a clean Linux Docker container, executes all CLI commands from `commands.md`, and writes each command's output below it. The same file is the test source and the golden output snapshot.

## Structure

```text
test/
├── README.md          <- you are here
├── commands.md        <- commands + output (source AND result)
├── run-tests.sh       <- bash runner: executes commands, writes output back
└── Dockerfile         <- clean Linux container with Python + git
```

## Quick Start

### 1. Build the image

From `tools_py/`:

```bash
docker build -t skills-python-smoke -f scripts/test/Dockerfile .
```

### 2. Run the test

```bash
docker run --rm -v ./scripts/test:/app/test skills-python-smoke
```

Output is written directly into `scripts/test/commands.md`.

### 3. Check the result

```bash
git diff scripts/test/commands.md
```

If everything is fine:

```bash
git add scripts/test/commands.md
git commit -m "smoke: update golden snapshot (python)"
```

## How It Works

`commands.md` uses the same format as the Go and Node.js snapshots:

```markdown
Some description of what we're doing

> `skills init --repo ../project-repo --groups group-1`
\`\`\`
output appears here after running
\`\`\`

> `skills list`
\`\`\`
output appears here
\`\`\`

More description text (ignored by the runner)
```

The runner (`run-tests.sh`):
1. Reads `commands.md` line by line
2. Extracts lines matching `` > `command` ``
3. Executes each command in the clean `/workspace` directory
4. Inserts combined output as a fenced code block
5. Replaces old output blocks on rerun
6. Preserves headings, descriptions, and command lines
7. Carries `cd` commands forward to subsequent commands

The Docker image provides a `skills` wrapper that runs `scripts/main.py`, so the snapshot command lines are identical to the Go and Node.js command lines.

## Adding a New Test

Add a command line to `commands.md`:

```markdown
> `skills create my-new-skill`
> `skills list`
```

Run the container, inspect the diff, and commit the snapshot when the output is correct.

## FAQ

**Q: Why Docker?**
A: It provides a clean Linux environment without artifacts from previous runs or dependencies on the host OS.

**Q: Can I run without Docker?**
A: Yes, on Linux. Run `bash scripts/test/run-tests.sh` with a `skills` wrapper or a compatible command available, plus Git and Python.

**Q: How do I validate results?**
A: Review `git diff scripts/test/commands.md`. A human or LLM validates the behavior from the snapshot diff.

**Q: Why do Git hashes and output details change?**
A: They are generated by each clean run. Review the structure and behavior; do not expect generated hashes to remain constant.

**Q: How does rerun work?**
A: The runner replaces only the content between output fences. Headings, descriptions, and command lines stay untouched.
